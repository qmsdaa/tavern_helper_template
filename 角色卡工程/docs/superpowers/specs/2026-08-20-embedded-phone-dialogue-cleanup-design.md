# 手机助手与对话渲染内嵌及工作区清理设计

## 目标

把当前手机助手和对话渲染的最新构建作为 TavernHelper 脚本内嵌进新卡；以最近的 `Counterfeit-v0.6.0-hotfix14-20260819.png` 为老版本基线做 fresh unpack 对比；在不丢失源码、用户素材和可交付产物的前提下清除本轮可重建临时文件。

## 构建链

1. 手机助手以 `前端工程/src/Counterfeit/界面/手机` 为源码，使用 `webpack.phone.config.ts` 构建单文件 HTML，再由 `pack_phone_script.py` 生成独立脚本 JSON，最后由 `sync_phone_artifacts.py --embed` 同步到卡内脚本与状态注册。
2. 对话渲染以 `角色卡工程/脚本/对话渲染.js` 为源码，由 `pack_dialogue_script.py` 刷新独立脚本 JSON；卡工程通过 `tavern-cards-state.json` 的 `script_file` 原样嵌入同一源码。
3. Forge 只从卡工程状态与文件打包，产出非覆盖式候选 PNG；候选和老卡都解包到临时 readback 目录。

## 对比边界

预期变化包括本轮精简的 MVU 更新规则/输出格式/Zod、手机助手、对话渲染，以及工作区中此前已经确认要随包交付的内容。必须重点检查：条目数量与名称无意外删减、150 幕场景清单完整、正则与基础元数据稳定、7 个 TavernHelper 脚本齐全、候选回读的手机/对话脚本与源文件逐字一致。

## 清理策略

- 保留：源码、规划/验证脚本、最终候选卡、已有发布卡、独立安装 JSON、用户素材、能说明未解决问题的报告。
- 删除：本轮烟测重复卡、本轮 fresh-unpack/比较缓存、可由命令稳定重建的临时目录。
- 对来源或用途不能完全确认的未提交文件只归类，不擅自删除。

## 验收

运行手机与对话专项测试、MVU/契约/EJS/场景审计、Forge pack/unpack、回读精确哈希检查和最终烟测；记录任何与本轮无关的既有失败。
